# 第三问并行计算改造与实測验收

已实现有界多进程和SCIP原生并发，**默认4进程、每进程1个SCIP求解线程**。32项测试通过，没有启动全年运行。

## 实测效果

| 相同负载 | 串行 | 并行 | 加速 |
|---|---:|---:|---:|
| 4个真实冻结输入的20场景、144时段、8秒预算MILP | 33.65秒 | 9.06秒，4进程且含启动 | **3.71倍** |
| 四节点各28个历史日的终端FD标定 | 1.878秒 | 0.553秒，复用热进程池 | **3.39倍** |

这批串并行实例的目标值、全局下界、gap和购电策略逐值一致，物理反馈映射误差为0；四个终端标定系数亦一致。实际记录到4个不同worker PID。单worker生命期峰值最高614.2 MiB；不能视为长时间全量搜索的内存上限，也不能与先前做过多线程试验的串行父进程高水位直接比较内存节省。

SCIP原生线程也真正启用并实测：单线程约8.42秒，两线程约9.79—9.96秒，四线程约10.00—10.18秒。这两个短测实例的gap没有因此改善，线程复制/启动增加了耗时与内存。所以保留 `--solver-threads` 选项，默认采用效果更好的独立进程并行。预算指求解预算，不能当作包含模型构建、拷贝和进程启动的严格墙钟上限。

这些是受限实例的**吞吐性能**，不是达到严格最优的耗时测量。这批仍未达到gap=0；并行不会自动解决分支定界收敛慢的问题。不能把此前主轨迹约6小时或全套约10天直接除以3.71，尤其单条SOC链有顺序依赖。

## 如何并行、如何保持模型一致

| 用户要求/模型边界 | 实现与验收 |
|---|---|
| 将单核计算改为并行 | `parallel.py`使用spawn进程池；实际4个worker并发处理4个冻结MILP |
| 单个MILP多线程能力 | `optimization.py`/`multistage.py`显式调用`solveConcurrent()`，并设置最小/最大线程数；不是只改一个没有生效的线程参数 |
| 全套独立实验 | 40条年度实验链（9×4敏感性+3额外OUV+M0）有界并行；已有主轨迹不重复计算；每条链内部按日期连续推进 |
| FIV纯信息价值 | 相同SOC/负荷/价格/历史索引的stale和updated两分支并行求解，按固定顺序汇合；只有父进程按原定义评价差额 |
| 终端标定加速 | 父进程先筛选当前日期之前已经完整实现的历史片段，再按历史日提交；FD辅助问题固定1线程，结果回写父进程缓存 |
| M2及结算稳健性 | 各stress日期并行；同一日期内部保持原条件树和各更新时间集合的同初态比较 |
| 避免超额并发 | 检查workers×solver_threads不超过当前可见CPU数；BLAS/OpenMP限制为1；年度实验worker内部不再启动子进程池 |
| 物理与因果一致 | 两条9日小范围SOC链串并行逐列一致；FIV费用/SOC及FD系数一致；保留原32项合并测试 |
| 不跑全量 | 默认命令为`parallel-benchmark`；只有显式`full`才能启动全年，本次未执行 |
| 错误不能冒充成功 | 保留LimitedSolve审计跨进程传递；独立链失败写任务清单并拒绝生成完整比较；输出目录重复即拒绝执行 |

进程数是计算资源设置，不改变S=20、尾部2、历史窗口、优化目标、终端残值或gap=0。当前机器可见10个CPU核心、16GiB统一内存；基于小样本内存及吞吐，默认选择4进程，没有直接占满10核。

## 使用方式

继续仅做小规模并行测试：

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 uv run --offline --with-requirements src/q3/requirements.txt python -m src.q3.run parallel-benchmark --workers 4 --seconds 8 --output outputs/q3/raw/new_parallel_test
```

之后明确需要全量时使用以下命令，**本次未运行**：

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 uv run --offline --with-requirements src/q3/requirements.txt python -m src.q3.run full --experiments --workers 4 --solver-threads 1 --output outputs/q3/raw/full_parallel
```

`--workers 1 --solver-threads 1`可恢复串行基线。`--solver-threads 2`可测试单问题原生并发，但本次短测不支持它比默认路线更快。主运行用持久池并行FIV/FD；全套实验将进程额度交给年度链，避免嵌套进程爆炸。场景数据只按任务序列化，不对同一个SCIP模型对象做跨进程共享。
