# 第三问计算并行化

## 用户要求与验收
1. 优化计算 → 保持原数学模型、场景、信息边界、精度，测量真实负载墙钟时间与解质量。
2. 单核太慢，改为并行 → 单MILP使用SCIP concurrent；独立实验/FIV/FD使用spawn进程池，报告实际并行数量。
3. 延续上轮不跑全量 → 仅小规模串并行对照，全年入口不启动。

## 计划
- [x] 重读开发规范、源码，核实10核/16GiB和SCIP原生并发支持。
- [x] 实现有界多进程与SCIP多线程、因果FD并行、FIV配对并行、独立实验并行。
- [x] 测试精确目标/物理一致性、非前瞻、异常传递和防嵌套超额并发。
- [x] 同输入串并行实际计时，按实测选择默认计算配置。
- [x] 报告界面冒烟、逐项验收、目录/变更记录同步。

## 决策
- 任何一条跨日SOC链仍按日期顺序；只并行相互独立的任务。
- solver线程与worker进程分别设置；限制BLAS/OpenMP线程，子实验不再建嵌套进程池。
- 继续gap=0，不把并行与放宽精度混为一谈。限时结果只作诊断。

## 错误记录
一次数值复核脚本误用未装NumPy的系统Python；改用项目现有uv锁定环境后通过。
